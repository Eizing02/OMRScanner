# กระดาษรุ่น 5 และสแกนต่อเนื่อง — 28 ตุลาคม 2569

## ขอบเขตที่อนุมัติ

ปรับหัวกระดาษ ตัวอย่างฝน QR สแกนต่อเนื่องโดยใช้ครึ่งแผ่นที่ตัดแล้วเป็นหลัก และเลือกยืนยันหลายคน พักการเพิ่มมาร์ค: คงสี่เหลี่ยมดำ 3 มม. สี่มุมเดิม ไม่มี ArUco/AprilTag หรือ dependency ตรวจมาร์คเพิ่ม

## กระดาษ

- การพิมพ์ใหม่ใช้ `school-v2` / geometryVersion 5 ชื่อโรงเรียนบรรทัดเดียว ปรับขนาดในขอบเขตหรือขยาย A4; ชื่อชุดสอบ 4.2 มม. ข้อมูลเติมใช้ตัวหนาจริงใน SVG/PDF
- QR 28 มม. ภาพ 512px และ quiet zone 4 modules; SAS2 ไม่เปลี่ยน ไม่มีข้อมูลนักเรียนใน QR
- ข้อมูลอยู่ซ้ายของ QR ชื่อยาวสองบรรทัดได้ ชั้น/ห้อง/เลขที่และรหัสมีจุดกำกับ ไม่สร้างเลขที่หรือห้องขึ้นเอง
- ตัวอย่างถูก/ไม่เต็มวง/สองวง/เลยวงอยู่ใต้กริดรหัส นอกพื้นที่คำตอบ คำแนะนำแบ่งคำไทยและใช้ความกว้างจริงของฟอนต์ ไม่ตัดกลางคำ
- คงพิกัดวงรหัส/คำตอบแบบ school แต่รุ่นและ QR identity แยกใหม่ ไม่เขียนทับแม่แบบเก่า classic 2 / compact 3 / school 4
- รองรับ 1–60 ข้อ 4/5 ตัวเลือก ขยายเต็ม A4 เมื่อไม่พอ ไม่ลดขนาดวง โลโก้ใช้ขั้นตอนรักษาสัดส่วนและ orientation เดิม

## กล้องและคิว

- ค่าเริ่มต้นครึ่งแผ่นและสแกนต่อเนื่อง ปิด checkbox เพื่อใช้ขั้นตอนตรวจภาพ/แก้มุม/ส่งทีละใบเดิม
- ล็อก QR ก่อน ใช้ Scanic และเกณฑ์ความละเอียด/ความนิ่ง/คุณภาพเดิม ภาพนิ่งตรวจขอบใหม่ ไม่ผ่อนเกณฑ์จากผลจำลอง
- ตรวจความชัดในกรอบคำตอบตามแม่แบบ ไม่ให้ QR รหัสพิมพ์ดำ หรือตัวอย่างฝนช่วยให้คำตอบเบลอผ่าน
- คิวหน่วยความจำมากสุดสามงาน รวมงานกำลังส่ง เก็บ JPEG ปรับมุมกับ Blob ต้นทางที่รักษาความละเอียดเดิม ส่งทีละคำขอ พักรับภาพเมื่อคิวเต็มหรือมีข้อผิดพลาด
- JPEG หลักเข้ารหัสครั้งเดียวที่ 0.85 ใช้ Blob และ request ID เดิมเมื่อลองส่งใหม่ เก็บ Blob ภาพนิ่งเดิม หรือ JPEG จากวิดีโอที่ความละเอียดเดิม เฉพาะกู้คืนในหน้านี้ ไม่อัปโหลด ไม่บีบอัดหลักซ้ำ
- หลังถ่ายต้องไม่พบกระดาษต่อเนื่องสามรอบจึงรับใบต่อไป ครูยกใบเก่าออกแล้ววางใบใหม่ ไม่ใช้ QR ร่วมเป็นตัวระบุนักเรียนหรือกันซ้ำ
- สำเร็จจึงนับว่าบันทึกและปล่อยภาพต้นทาง ล้มเหลวยังคง Blob ให้ลองส่งหรือเปิดตรวจภาพ Timeout 45 วินาทีไม่แปลว่าเซิร์ฟเวอร์ไม่ได้บันทึก: ลองใหม่ด้วย ID เดิมเสมอ
- กล้องเปิดระหว่างส่ง ยังถ่ายมือ/ปิดกล้องได้ ซ่อนหน้าหยุด stream/worker/cache โดยรักษาคิวเท่าที่หน้ายังอยู่ เปลี่ยนบัญชี/พื้นที่หรือ unmount ยกเลิกงานและคืนทรัพยากร
- เตือนก่อนปิดหน้าและกันคลิกลิงก์ภายในระหว่างรอส่ง แต่ไม่รับรองกู้คืนหลัง process crash, แท็บถูกระบบทิ้ง หรือ browser Back ไม่มี offline persistence/background upload
- ทุกผลเริ่ม pending_review การกันซ้ำและการแทนที่ผลรอยืนยันเดิมยังอยู่ ไม่สแกนทับคะแนนยืนยันแล้ว

## ยืนยันหลายรายการ

- เตรียมสถานะล่าสุดจาก DB ของรายการในหน้าปัจจุบัน สูงสุด 50 รายการ ไม่ถือว่าเป็นทั้งห้อง/ทั้งคิว
- เลือกเฉพาะงาน pending ที่มีนักเรียนและคำตอบครบ ไม่มี ambiguous/unreadable รายการมีปัญหาปิด checkbox พร้อมเหตุผล
- ส่ง revision ที่พรีวิว ผ่าน `review_scan` เดิมใน transaction ย่อยรายคน stale/locked/uncertain ไม่ข้ามตรวจ และไม่ทำให้คนอื่นสูญหาย
- รายงานผลรายรายการและใช้ audit เดิม Retry หลัง network response หายไม่เพิ่มคะแนน/audit ซ้ำ
- ไม่เปิด/เปลี่ยนการตั้งค่า MathQuest; publication hooks ที่เคยยินยอมยังทำงานตามนโยบายเดิม เจ้าของดูพื้นที่คนอื่นยัง read-only

## ติดตั้ง

เตรียมและทดสอบใน PostgreSQL จำลอง ยังไม่ได้ติดตั้ง production หรือเปลี่ยน env/data จริง

อัปเดตหลังส่งมอบ: ผู้ใช้แจ้งว่ารัน SQL แล้วและอนุญาตให้พุชเข้า main การติดตั้งจริงยังไม่ได้ตรวจยืนยันโดยเอเจนต์ ไม่ต้องรันซ้ำหาก 017/018 สำเร็จแล้ว

หากติดตั้ง 013–016 แล้ว รันใน Supabase SQL Editor ตามลำดับ **ครั้งเดียว**:

1. `supabase/migrations/202610280017_print_v5.sql`
2. `supabase/migrations/202610280018_batch_confirmation.sql`

แต่ละไฟล์มี transaction/prerequisite guard ไม่รัน schema.sql ซ้ำ ไม่แก้ SQL เก่า ไม่ลบข้อมูลเดิม ตรวจด้วย:

```sql
select version from private.app_installation
where version in ('202610280017','202610280018') order by version;
```

จากนั้น deploy โค้ดนี้ ทดสอบบัญชีจริง: PDF ใหม่ → พิมพ์ 100% → สแกน → ยกออก → ใบถัดไป → ตรวจข้อที่มีปัญหา → ยืนยันหลายคน ต้องผ่านงานพิมพ์/อุปกรณ์จริงก่อนใช้คะแนนจริง

## ย้อนกลับ

ก่อนออกกระดาษรุ่น 5 กลับโค้ดเดิมได้และเก็บ SQL ไว้ หลังออกกระดาษรุ่น 5 ต้องคงตัวอ่าน/ตำแหน่ง QR/ฟอนต์รุ่น 5 ห้ามย้อนเป็นโค้ดที่อ่าน school-v2 ไม่ได้หรือแก้ registry เดิม ปิดต่อเนื่องด้วย checkbox และใช้ยืนยันรายคนได้ทันที ไม่ลบ scan/template/result/audit เพื่อย้อนคุณสมบัติ

## ระบบเช็คชื่อ / MathQuest

รอบ 017/018 ไม่เปลี่ยน wire contract `schema_version: 1.0`, student_code ห้าหลัก, pairing, ACK หรือรูปแบบผลคะแนน จึงไม่ต้องแก้โค้ด/SQL/env ฝั่งรับสำหรับคุณสมบัติรอบนี้ การยืนยันหลายคนเรียก review_scan เดิม และคง publication hooks ตามโหมด/ความยินยอมเดิม การยืนยันคะแนนยังแยกจากการส่งคะแนน: manual ต้องสั่งเผยแพร่ ส่วน auto_after_confirm ใช้ได้เฉพาะที่เคยเปิดและมี runner พร้อม ไม่ส่งรูปภาพ QR หรือตัวอย่างฝนให้ MathQuest ควรลองข้อมูลทดสอบหนึ่งชุดหลัง deploy เพื่อยืนยันการเชื่อมสด; ผลทดสอบในเครื่องไม่ยืนยันสถานะ receiver/runner จริง
