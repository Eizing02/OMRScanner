# หลักฐานการออกแบบรายชื่อสี่คอลัมน์ — 9 ตุลาคม 2569

ส่วนเสริมนี้อยู่ในโหมด Operate ของหน้ารายชื่อและนำเข้าที่มีอยู่ ครูเทียบ `รหัสประจำตัว`, `ชื่อ`, `นามสกุล`, `ระดับชั้น` กับไฟล์ต้นฉบับก่อนยืนยันนำเข้า ตาม [surface brief](../.impeccable/surfaces/components-students-import-preview-table-tsx.md). สืบทอดทิศทาง “เส้นทางตรวจข้อสอบ” และ seed `19bece82` จาก [DESIGN.md](../DESIGN.md) และ `.impeccable/design.json` ไม่มีการเลือกโลกภาพหรือ comp ใหม่

## ระบบภาพที่คงไว้

| หลักเดิม | หลักฐานในส่วนเสริม |
| --- | --- |
| Noto Sans Thai และลำดับข้อความเดิม | ป้าย mapping และหัวตารางเป็นภาษาไทย ใช้ฟอนต์และความหนาแน่นเดิม ไม่เพิ่มสเกลตัวอักษร |
| แถบนำทางน้ำเงินหมึก ผืนงานขาวเย็นและแผงขาว | ภาพ desktop/mobile ทั้งสี่คง shell, สีและเส้นแบ่งเดิม |
| แผงพื้นราบ มุม ช่องกรอกและปุ่มเดิม | ใช้ native selects มีป้าย ปุ่มหลักน้ำเงิน notices และ badges เดิม ไม่เพิ่มเงาตกแต่ง |
| Meaning Before Color, Thai Reading, Flat Seam | สถานะมีคำไทยและเครื่องหมายประกอบ ตารางและฟอร์มยังอ่านตามลำดับงาน ไม่เพิ่มกฎเฉพาะรายชื่อเป็นมาตรฐานทั้งแอป |

`DESIGN.md` และ `.impeccable/design.json` ถูกเก็บไว้โดยไม่แก้ไข การจัดสี่ mappings เป็นแถวบน desktop และสองคอลัมน์บนมือถือใช้กฎ `.roster-mapping` เฉพาะหน้าจอใน `app/globals.css`; เป็นการปรับในระบบเดิม ไม่มี token หรือ component primitive ใหม่

## พฤติกรรมที่ส่งมอบเฉพาะหน้าจอ

- `/students/import`: คำแนะนำ ตัวอย่าง CSV และ mappings หลักเรียงตามสี่คอลัมน์ต้นฉบับ พรีวิวเพิ่มหมายเลขแถวและผลตรวจรอบสี่คอลัมน์ แสดงคำนำหน้าร่วมกับชื่อและเก็บศูนย์นำหน้ารหัส
- ส่วนชื่อ-สกุลรวมและเลขที่อยู่ใน details ซึ่งเปิดอัตโนมัติเมื่อพบชื่อ-สกุลรวม รองรับไฟล์สามคอลัมน์เดิมและไม่สร้างเลขที่เอง
- `/students`: ตารางใช้สี่คอลัมน์เดียวกัน คงการค้นหา กรองระดับชั้น/ห้อง จำนวนรายชื่อและแบ่งหน้า
- มือถือ: mappings เป็นสองคอลัมน์ ตารางมีพื้นที่เลื่อนภายในพร้อมชื่อและรับโฟกัสคีย์บอร์ด หน้าไม่ต้องขยายกว้างตามตาราง การปรับนี้ไม่เปลี่ยน visual authority ของระบบเดิม
- คงการตรวจรหัสซ้ำในไฟล์และทะเบียน ไม่ merge เลื่อนชั้น หรือเขียนทับรายชื่อเดิมโดยอัตโนมัติ งานนี้ไม่ได้เพิ่มประวัติสมาชิกห้องแยกตามเทอม/ปี

ภาพเหล่านี้เป็นหลักฐานหน้าจอของส่วนเสริม ไม่ใช่ raster ใหม่ในผลิตภัณฑ์ งานนี้ไม่มีการสร้าง/แก้ asset ภาพหรือเปลี่ยน provenance ของ raster ที่ใช้งานอยู่ หลักฐานโลโก้เดิมยังอยู่ใน [ROSTER_LOGO_DESIGN_EVIDENCE.md](ROSTER_LOGO_DESIGN_EVIDENCE.md); รอบนี้ไม่ได้ตรวจ provenance ของภาพทั้งผลิตภัณฑ์ใหม่

## คำตัดสิน finish reviewer

ตามผล finish reviewer อิสระที่ผู้ดำเนินงานส่งให้ documenter: `disposition: ship` เป็นคำตัดสินสำหรับส่วนเสริมนำเข้า/แสดงรายชื่อสี่คอลัมน์ ไม่ใช่คำตัดสินอิสระของ documenter

| ด้านที่ตรวจ | ผลที่ได้รับ |
| --- | --- |
| Persistence | ตรงกับ `PRODUCT.md` รูปแบบปัจจุบันสี่คอลัมน์และไฟล์เดิมสามคอลัมน์; คง `DESIGN.md`, sidecar และ inherited direction |
| Fidelity | สอดคล้องกับระบบเดิมและ direction contract; ภาพทั้งสี่ตรงกับหน้าจอและอุปกรณ์ที่ระบุ |
| Finish ceiling | ถึงขอบเขตงานต่อเติมในระบบเดิม ไม่ต้องเพิ่มการตกแต่งหรือเปลี่ยนโลกภาพ |
| Material fixes | ไม่มีภายในส่วนเสริมที่ตรวจ |
| Keep | คงศูนย์นำหน้า คำนำหน้า legacy import การตรวจรหัสซ้ำ ตารางและตัวกรอง; mappings สองคอลัมน์กับการเลื่อนตารางมือถือเป็นการปรับตามอุปกรณ์ในระบบเดิม |

ผลอัตโนมัติที่ผู้ดำเนินงานบันทึกไว้: unit 83/83, E2E current/legacy roster และโลโก้ 7/7, ESLint/typecheck/production build ผ่าน; Impeccable detect บน TSX ที่เปลี่ยนทั้งสองไฟล์ไม่พบ findings และ Axe desktop/mobile ไม่พบข้อผิดพลาดที่ตรวจอัตโนมัติ รายละเอียดและข้อจำกัดอยู่ใน [CURRENT_ROSTER_ALIGNMENT.md](CURRENT_ROSTER_ALIGNMENT.md). Documenter ไม่รันทดสอบหรือ detector ซ้ำ

## ความคลาดเคลื่อนเดิมและขอบเขตหลักฐาน

Narrative ของ sidecar สำหรับ Designer มือถือยังอธิบายการดูพรีวิว/นำทางเป็นหลัก ขณะที่ `DESIGN.md` และ controls ที่อนุมัติแล้วระบุจำนวนข้อ ช้อย ขนาดกระดาษ และโลโก้แบบพับได้ ข้อความ Stack บางส่วนใน `PRODUCT.md` ยังสะท้อน blueprint ที่วางแผนไว้ก่อนหน้า ความคลาดเคลื่อนทั้งสองเป็นของเดิมและอยู่นอกงานรายชื่อนี้ จึงรายงานโดยไม่ซ่อมหรือใช้เป็น design canon ใหม่

การเทียบ live Supabase ครอบคลุม metadata ของ `public.students` 13 คอลัมน์ผ่าน SELECT เท่านั้น โดยผู้ดำเนินงานไม่ได้อ่านข้อมูลบุคคลหรือเขียนข้อมูลนักเรียนขึ้นคลาวด์ ไม่ต้องเปลี่ยน SQL สำหรับ alias ใหม่ การเทียบไฟล์ผู้ใช้ทั้ง 202 แถวทำเฉพาะในเครื่องและไม่ได้นำรายชื่อจริงลง fixtures/Git

คำตัดสิน ship ไม่รับรอง Auth ที่ใช้งานจริง การนำเข้าข้อมูลจริง การตรวจ RLS ทุกกรณี หรือความแม่นยำ OMR/คะแนนทั้งผลิตภัณฑ์ ยังไม่มี commit/push/deploy ของส่วนเสริมนี้ และไฟล์ XLSX/CSV ต้นฉบับไม่ได้ถูกแก้ไข

รอบ documenter เพิ่มไฟล์นี้และแก้เฉพาะส่วนท้ายของ `docs/CURRENT_ROSTER_ALIGNMENT.md` เพื่อบันทึกคำตัดสินและสรุปไฟล์ ไม่แก้โค้ด SQL/schema global tokens ภาพ `PRODUCT.md`, `README.md`, `DESIGN.md` หรือ sidecar
