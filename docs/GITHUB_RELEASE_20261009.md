# ชุดเผยแพร่ GitHub — 9 ตุลาคม 2569

ขอบเขต commit: รวมงานเสริมที่ผู้ใช้อนุมัติและงานปรับรูปแบบรายชื่อปัจจุบัน เข้าสู่ `main` ของ `Eizing02/OMRScanner` โดยไม่เปลี่ยนโครงสร้างโปรเจกต์ การ push ไม่ทดแทนการยืนยันว่า Netlify deploy สำเร็จหรือ Google OAuth พร้อมใช้งาน

## ส่วนที่รวมในชุดนี้

- หน้านำเข้า/ตาราง/ตัวอย่าง CSV ใช้ `รหัสประจำตัว,ชื่อ,นามสกุล,ระดับชั้น` รองรับรูปแบบชื่อ-สกุลรวมเดิม รหัสเป็นข้อความ 5 หลักและรักษาศูนย์นำหน้า ตรวจรหัสซ้ำก่อนบันทึก
- API นำเข้าหา `school_id` จากบัญชีและพื้นที่ที่ได้รับสิทธิ์แล้ว ไม่ให้ผู้ใช้กรอกหรือปลอม UUID ในไฟล์ CSV; ต้องนำเข้าผ่านเว็บแอป ไม่ใช่ Supabase Table Editor
- บัญชี Google, pending/approved/rejected/suspended, พื้นที่ส่วนตัวของครู และเจ้าของระบบอนุมัติ/ระงับและเปิดดูพื้นที่อื่นแบบอ่านอย่างเดียว
- การตั้งค่า วิชา และ dropdown ชั้น/ห้องจากรายชื่อที่มีจริง
- โลโก้ original PNG/JPG ใน private Supabase Storage, การเปลี่ยน/ลบภาพเก่าที่ตรวจสอบได้ และใช้โลโก้ล่าสุดเมื่อพิมพ์ซ้ำ
- พิมพ์กระดาษรายบุคคล พร้อมชื่อ รหัสและช่องรหัสที่ฝนไว้ QR ร่วมของชุดสอบ และทะเบียนแม่แบบ/ชุดพิมพ์ที่ไม่เขียนทับรุ่นเก่า
- migrations 003–005 และ snapshot สำหรับติดตั้งใหม่ รวมเอกสารติดตั้งและชุดทดสอบ ไม่รัน SQL บนฐานข้อมูลจริงในรอบ push นี้ และไม่รัน snapshot ทับฐานข้อมูลเดิม

ไม่รวม `.env.local`, คีย์ลับ, รายชื่อ Excel/CSV จริง, สคริปต์ตรวจข้อมูลชั่วคราว หรือภาพ screenshot ของการทดสอบ ไม่มีการนำเข้าหรือเปลี่ยนข้อมูลนักเรียนจริงในรอบนี้

## งานฝั่งบริการที่ต้องพร้อมก่อนนำเข้าจริง

1. Netlify ต้อง deploy commit ล่าสุด และมี `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `NEXT_PUBLIC_DEMO_MODE=false` ตอน build
2. เปิด Google provider ใน Supabase ด้วย OAuth client ของเจ้าของ ตั้ง callback/redirect ตาม `docs/SUPABASE_GOOGLE_SETUP.md` ไม่ใส่ Google Client Secret ใน GitHub หรือ frontend
3. จัดการ legacy service-role key ที่เคยเปิดเผยก่อนใช้ข้อมูลจริง ห้ามใช้คีย์นี้เพื่อข้ามบัญชีหรือ RLS
4. เข้าสู่ระบบด้วยบัญชีเจ้าของที่กำหนด ให้ระบบสร้าง/ยืนยันพื้นที่ แล้วเปิด นักเรียน → นำเข้ารายชื่อ → เลือกไฟล์ต้นฉบับเพียงหนึ่งไฟล์ → ตรวจ 202 คน → ยืนยันนำเข้า

การยืนยันคอลัมน์ `students` บน Supabase สดไม่รับรองการติดตั้งทุก migration/สิทธิ์หรือ Google Login ทั้งหมด การ push และผลทดสอบแบบ mock ไม่ใช่ live Supabase E2E

ระบบอ่าน QR/รหัส/คำตอบจากภาพจริง บันทึกคะแนน ตรวจทาน และรายงานคะแนนจริงยังอยู่นอกชุดงานที่เสร็จ ไม่ประกาศว่า OMR ทั้งผลิตภัณฑ์พร้อมเก็บคะแนน
