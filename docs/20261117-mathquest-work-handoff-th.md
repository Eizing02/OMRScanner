**ไฟล์อ้างอิงที่ส่งพร้อมใบงาน** จาก repo ScanSob (`Eizing02/OMRScanner`) ใช้ `lib/integrations/mathquest/contract.ts` และ `tests/score-integration-event-fixture.ts` จาก checkout ที่จะทดสอบ หากรับไฟล์ใบงานแยก ให้ขอสองไฟล์นี้จากทีม ScanSob เพื่อเทียบสัญญากับโค้ดชุดเดียวกัน

## เป้าหมายของงาน

เมื่อครูยืนยันคะแนนใน ScanSob และกดส่งจากหน้าผลสอบ MathQuest ต้องรับคะแนนเข้ารายงานของโรงเรียนที่อนุมัติ แจ้งจำนวนที่รับและรายการที่ต้องแก้ และให้ผู้เรียนเห็นเฉพาะคะแนนของตนตามสิทธิ์ที่ MathQuest เปิดไว้ การขอเชื่อมพื้นที่ทำงานโดยไม่กรอกรหัสเป็นงานถัดไป หลังจากยืนยันการส่งคะแนนผ่านการเชื่อมต่อเดิมบน staging

## สิ่งที่ ScanSob ส่งมอบแล้วในเครื่อง

- พรีวิวก่อนส่งแสดงโรงเรียนปลายทาง ข้อมูลชุดสอบ ยอดยืนยันแล้ว รอตรวจ และรับแล้ว ตัวส่งใช้ผลที่ยืนยันแล้วและอ่านรหัสนักเรียนห้าหลักจากหลักฐานตอนสอบ หากหลักฐานขาดหรือรหัสต่างจากทะเบียนที่ผูกกับผลสอบจะระงับการสร้างรอบส่งใหม่ให้ตรวจสอบก่อน
- แบบพิมพ์ใหม่มี A4 แนวนอนสองใบต่อแผ่นและ A4 แนวตั้งหนึ่งใบต่อแผ่น การพิมพ์ สแกน QR อ่านวง และให้คะแนนเป็นงานใน ScanSob ฝั่ง MathQuest รับผลผ่าน API คะแนนเดิม
- ทดสอบตัวรับ MathQuest ในฐานข้อมูลจำลองแล้ว โดยใช้การอนุมัติแบบเดิม ผลคือรับ 1 รายการ แจ้งรหัสไม่พบ 1 รายการ ส่งซ้ำได้ใบตอบรับเดิม และถอนผลได้ ผลนี้เป็นหลักฐานในเครื่อง รอทดสอบตัวรับที่ deploy และบัญชีผู้ใช้บน staging
- SQL **021, 022 และ 023** เป็นของ Supabase **ScanSob** ให้ทีม ScanSob ติดตั้งตามลำดับหลัง 020 เมื่อได้รับอนุมัติ ฝั่ง MathQuest ให้ตรวจเวอร์ชันตัวรับและ migration ของ repo ตนเอง

## งานที่ 1 · ตรวจรับคะแนนบน staging ผ่านการเชื่อมต่อเดิม

**1. ตรวจตัวรับและฐานข้อมูล** เริ่มจากตัวรับโปรไฟล์ 1.1 และ recovery migration `20261015_03_scansob_recovery_hardening.sql` ตรวจการติดตั้งจากฐาน staging ก่อนจัดเตรียม migration ที่ขาด ใช้ `supabase/functions/ingest-scansob-results/index.ts` และชุดทดสอบที่มีอยู่เป็นจุดเริ่มต้น

**2. ยืนยันสัญญาข้อมูล 1.0** ตัวรับ `POST /functions/v1/ingest-scansob-results` รับ token เฉพาะการเชื่อมต่อที่ยังใช้งานและมีสิทธิ์ `score:write` ผูกข้อมูลกับโรงเรียน พื้นที่ทำงาน และชุดสอบต้นทาง ใช้ชื่อฟิลด์และเงื่อนไขจาก [สัญญา ScanSob](../lib/integrations/mathquest/contract.ts) และ [ข้อมูลทดสอบ](../tests/score-integration-event-fixture.ts)

ข้อมูลคะแนนแลกเปลี่ยนผ่านผลสอบที่ยืนยันแล้วและรหัสตามสัญญา ส่วนภาพสแกน QR ตราโรงเรียน ชื่อผู้เรียน และเฉลยเป็นข้อมูลของต้นทาง สำหรับรายการรหัสไม่พบ ให้แสดงเหตุผลในรายงานครูและให้ ScanSob สร้างรอบใหม่หลังแก้ทะเบียน การส่งชุดเดิมซ้ำมีไว้กู้ใบตอบรับของชุดเดิม การเอารายการออกจากรอบใหม่อย่างเดียวไม่ลบคะแนนที่เคยรับ

**3. ตรวจรายงานครูและหน้าคะแนนนักเรียน** ให้ครูเห็นชื่อชุดสอบ วิชา ห้อง เทอม/ปี คะแนนเต็ม คะแนนที่ได้รับ และแยกจำนวนรับสำเร็จออกจากรายการรหัสไม่พบ ตรวจหน้า **คะแนนสอบของฉัน** ให้ใช้ Google และรหัสนักเรียนที่ยืนยันแล้วตามนโยบายเดิม เมื่อสลับรหัสให้โหลดคะแนนของรหัสที่เชื่อมล่าสุดผ่านสิทธิ์ที่ตรวจจาก session การเปิดให้นักเรียนดูคะแนนใช้ตัวเลือกของ MathQuest และแสดงหลังรับชุดย่อยครบตามเงื่อนไขเดิม

**4. ทดสอบกับ ScanSob บน staging** ใช้สองนักเรียนจำลองและอย่างน้อยสองพื้นที่ทำงานทดสอบ โดยมีหนึ่งรหัสที่พบและหนึ่งรหัสที่ยังไม่อยู่ในทะเบียนปลายทาง ทดสอบกดส่งเองก่อน สถานะใน ScanSob ต้องเปลี่ยนตามใบตอบรับ และทั้งสองฝั่งต้องเทียบยอดได้จากชุดสอบและเลขรอบเดียวกัน

## งานที่ 2 · ปิดงานจับคู่พื้นที่ทำงานแบบไม่กรอกรหัส

ใน workspace ของ MathQuest มีร่าง `20261116_01_scansob_code_free_pairing.sql`, `scansob-inbox.js` และชุด `test-scansob-signed-pairing.cjs` แล้ว ใช้ `docs/20261116-scansob-code-free-pairing-handoff.md` เป็นรายละเอียดตั้งต้น ส่วน ScanSob ยังส่งคำขอจับคู่แบบเดิม ให้ปรับร่างและส่งสัญญาที่ตกลงร่วมกันกลับทีม ScanSob ก่อนเพิ่มการส่งแบบใหม่

1. **ป้องกันคำขอซ้ำทั้งสองทาง** ใช้กติกาเดียวกันกับ `request` และ `request_signed` ให้โรงเรียนหนึ่งมีคำขอรอหรือการเชื่อมต่อ active ได้หนึ่งรายการต่อ Workspace ตรวจในธุรกรรมก่อนใช้รหัสจับคู่หรือสร้างคำขอ ทดสอบทั้งลำดับเก่า→ใหม่ และใหม่→เก่า
2. **กำหนดรอบการเปิดรับของฝั่ง MathQuest** ตกลงให้ตัวรับออกรหัสระบุรอบการเปิดรับ และยืนยันรอบนั้นในสัญญาที่ ScanSob ลงนาม เมื่อรีเซ็ตและเปิดรับใหม่ คำขอจากรอบเดิมต้องเปิดขึ้นมาเองไม่ได้แม้เวลาสองเครื่องคลาดกัน ให้ส่งรูปแบบ capability และ error/ACK ตกลงร่วมกันก่อนแก้ schema ของ request
3. **ตรวจสิทธิ์ตอนรับและตอนอนุมัติ** ผู้ดูแลกำหนดอีเมลที่อนุญาตในโรงเรียนปลายทาง หน้าอนุมัติแสดงอีเมล Google ที่ยืนยันแล้ว ชื่อ Workspace และเวลาคำขอ ตรวจสิทธิ์ อายุกับสถานะอีกครั้งขณะอนุมัติ คำนึงถึงกรณียกเลิกหรือหมดอายุพร้อมกัน
4. **ให้กล่องคำขออ่านจาก API ที่มีสิทธิ์** อินบ็อกซ์ใช้สิทธิ์ครู Google และ session ผู้ดูแลตามเดิม เปิดใช้การตรวจเป็นรอบได้ก่อน หากเปิด Broadcast ให้ใช้ช่องส่วนตัวส่งเพียงสัญญาณให้หน้าจอโหลดรายการใหม่ และตรวจการเข้าอ่านด้วยสิทธิ์ผู้ดูแลจริง
5. **ส่งสัญญาการกู้คำขอกลับ ScanSob** จัดทำตัวอย่างสำหรับคำขอเดิมที่ตอบกลับหาย การอนุมัติ ปฏิเสธ หมดอายุ และยกเลิก ผูกคำตอบกับ request ID และโรงเรียนกำหนดไว้ เมื่อผลส่งยังไม่แน่ชัด ScanSob จะลองส่งคำขอเดิมก่อนถามสถานะ การจับคู่สำเร็จเปิดสิทธิ์ให้กดส่งคะแนนตามเดิม

## สิ่งที่ให้ทีม MathQuest ส่งกลับ

- ลิงก์ PR หรือ commit และรายชื่อไฟล์ที่เปลี่ยน รวมเวอร์ชัน SQL/Edge Function ของ staging ที่ทดสอบจริง
